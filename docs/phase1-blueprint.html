Section 04

The standout “wow” feature

Billing Day Time-Travel Simulator — kept from the default proposal, sharpened so it proves the two hardest invariants.

Why it beats the alternatives

It is the core feature, its effect is measurable live in front of judges, and it proves idempotency and snapshot immutability rather than describing them. An AI copilot panel would demo conversation, not correctness.

What it does

  1. Simulate Billing Date picker. today lives in the global store, so every page's overdue logic and is_overdue recompute together.
  2. Run Billing Day Batch animates a five-stage pipeline: Due subscriptions found (n) → Discount check → Tax computation → Invoice created → Invoice sent, each stage ticking with animate-in fade-in slide-in-from-bottom-2.
  3. Live KPI deltas: MRR ↑, Outstanding ↑, Overdue ↓ after reminders.
  4. Press Run again — every record returns SKIP with billing_period_key already exists and the toast reads “0 invoices created · 37 already billed — nothing billed twice.”
  5. A Run Ledger panel lists every decision (BILL / SKIP / AUTO_CLOSE + reason), so the idempotency proof is auditable rather than a single toast.
  6. Time-travel +1 month — renewals advance with real addMonths math (Jan 31 → Feb 28) and auto-close fires on expiry_date when auto_close is true.

Pipeline contract

Due subscriptions→ Idempotency key check→ Discount window + usage→ Tax rules→ Invoice snapshot→ Send / Ledger

Supporting pure modules

ModuleResponsibility
money.tsroundHalfUp2 (sign-aware, mirrors Python Decimal.ROUND_HALF_UP), sumLines, INR formatter re-export
dates.tsaddCycle(date, freq) via addDays/addWeeks/addMonths/addYears; diffDays; isWithinWindow
payments.tsapplyPaymentToInvoice(invoice, payments) → { status, amount_paid, amount_due, is_overdue }; CONFIRMED → PARTIALLY_PAID → PAID; refuses overpayment
billingBatch.tsrunBillingDayBatch(state, today_str) → { state, report }. Per-subscription try/catch, increments current_uses only on a created invoice, returns new slices
snapshots.tsbuildInvoiceLines(...) — the only place invoice lines are created; nothing reads live catalog afterwards

Math, stated once

Unit = Base + VariantExtra→ Gross = Unit × Qty→ Discount gate→ Taxable = Gross − Discount→ Tax = Taxable × rate / 100→ Line total = Taxable + Tax

Discount applies only when: today inside [valid_from, valid_until], qty ≥ min_qty, gross ≥ min_purchase, and uses_left > 0. Rounding is half-up to 2 decimals at the line level only.

Section 10

Judge-breaker edge cases

Each one is visible in the UI, not buried in code — that is the difference between a demo and a system.

Edge caseWhere the judge sees itMechanism
Double-billing guard /billing — run the batch twice billing_period_key set → SKIP + “0 created · 37 already billed” toast; Run Ledger shows SKIP reasons
Snapshot immutability /invoices/:id after editing a Product price in Studio Invoice renders *_snapshot columns only; before/after price banner proves the invoice is unchanged
Discount expiry / usage exhaustion /catalog/discount-rules + next billing run Past valid_until or current_uses ≥ max_uses → discount_applied: false; row shows 48/50 then 50/50 — exhausted
Pause date shift /subscriptions/:id — pause 10 days, then resume next_billing_date and expiry_date shift by exactly 10 days; ribbon shows PAUSED with paused_at
Partial payments /invoices/:id — pay ₹1,000 of ₹3,020 CONFIRMED → PARTIALLY_PAID → PAID, amount_due recomputed, KPI Outstanding drops
Plan-flag-disabled buttons /subscriptions/:id on Annual Enterprise Plan (can_close_early: false) Disabled + tooltip “This plan does not allow early closure” — enforced by checkSubscriptionTransition, not the button
One bad record doesn't block the batch /billing failed strip Per-subscription try/catch → failed[] rendered as amber rows while the rest succeed
Tax computed from rules Invoice lines tax_percent_snapshot from the Tax Rule (GST 18%), never hardcoded
Unique email / password policy /signup Live checklist (9+, upper, lower, special) + duplicate-email error before submit
No double charge on cancel /invoices/:id — cancel CANCELLED invoices excluded from outstanding/overdue and from period-key reuse
Enforcement principle

Business rules live in the reducer and the mirrored engine, never in the view. Buttons are disabled because the engine refused, so a judge cannot click through the UI into an illegal state.

Section 11

Three-minute demo story

One continuous narrative: billing day is due, renewals are about to lapse, overdue invoices threaten revenue, a discount auto-applies — and after the actions MRR rises while Overdue falls.

TimeActionWhat judges see
0:00–0:15Open /dashboard as ADMINKPIs load, Query Time: 38 ms, 1,850 active, ₹48.2L MRR, ₹6.4L outstanding, 412 overdue
0:15–0:35Click Run Revenue Insights1.5 s spinner → red “412 overdue at risk”, yellow “9 renewals within 7 days”, green “10% Off 10+ Seats will auto-apply”

0:55–1:15What-if: Annual Enterprise, YEARLY, qty slider 5 → 12, discount ON, GST 18%Projected MRR recalculates live: ₹2,560 × 12, 10% off, 18% tax

2:00–2:20Open a generated invoice → Record Payment ₹2,000 of ₹3,020PARTIALLY_PAID, amount_due ₹1,020, dashboard Outstanding drops; second payment → PAID

Why this order works

  • Opens with the finance question, not with configuration — matches the primary user.
  • Every subsequent click moves a number the judge has already seen.
  • The second billing run converts a claim into a proof.
  • Closes on role isolation, the requirement most likely to be faked elsewhere.
